# CrateLoom

For the current project overview, implemented features, limitations, development runbook, and active YouTube mix issue, see [PROJECT_HANDOFF.md](PROJECT_HANDOFF.md).

A local-first DJ preparation application. This repository is an early development prototype, not a release: see [docs/PROGRESS.md](docs/PROGRESS.md) for the precise feature and verification boundaries.

## Development on macOS

Requirements: Node.js 22+, npm, Rust, Python 3, and `ffmpeg` and `ffprobe` on PATH. The host engine uses Python's standard library; optional analysis and tag-writing workers use separate pinned environments. Run from the repository root:

```sh
./scripts/dev-macos.sh
```

If port 1420 is already in use, run `CRATELOOM_DEV_PORT=1421 ./scripts/dev-macos.sh` instead. Quit any older CrateLoom window using the same library before upgrading; schema migration creates a SQLite backup.

The native-storage copy avoids AppleDouble `._*` files generated by shared drives, which otherwise break Tauri capability parsing. The script refreshes the copy each time it runs. A Python executable can be selected with `CRATELOOM_PYTHON`. For the experimental frozen engine, set `CRATELOOM_ENGINE_EXEC` to its full path instead. See [M0 verification](docs/M0_VERIFICATION.md) for results and a hands-on checklist. The engine stores data in `~/.crateloom`; set `CRATELOOM_DATA` to isolate a test library. Original audio is referenced, not copied or modified. A development build needs the source tree and installed Python and FFmpeg; it is not a distributable app.

```sh
npm run build
npm test
python3 -m unittest discover -s engine/tests -v
CARGO_TARGET_DIR="$HOME/Library/Caches/CrateLoom/target" COPYFILE_DISABLE=1 cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml
```

## Optional beat and RGB analysis

On Apple Silicon macOS, run `./scripts/setup-analysis-macos.sh` once before starting the app to enable offline beat estimation and the frequency-colored waveform. See [M2 verification](docs/M2_VERIFICATION.md) for controls, testing and limitations. An optional local structure model adds automatically labeled sections after running `./scripts/setup-structure-macos.sh`; review its weight-license discrepancy and the labels before use.

## Try the local workflow

Select one or multiple audio files with Add Music, or use the folder button to scan a folder recursively. The import report shows added, duplicate, and failed files; Cancel keeps completed results. BPM/RGB analysis queues automatically. Use the Missing files filter and Relink to locate moved files; replacements must match the original audio. See [M3 verification](docs/M3_VERIFICATION.md). Open **Edit Cues**, seek and add a cue, edit its label or time, then try dragging its waveform marker and undo/redo. Quit and restart the app to check persistence. Export to a new XML filename and check the companion JSON backup. The source file is referenced and is never modified on import or export.

The audio-stream signature guards against applying cues to a replaced file. For a track imported by an earlier version, open it once while the original file is still unchanged to establish the signature. Missing files can be relinked to matching audio; a different mix or re-encoded version is rejected. Beat positions and cue suggestions are estimates to review; sections can be entered manually or generated by the optional model. BPM and global grid positioning are editable; flexible beat-warp markers are not yet available.

## Export

Open a saved playlist and choose **Export playlist**, or select library rows and choose **Export selected**. **Copy audio** puts verified copies next to the XML; leave it off to reference your files. **Export XML** in the cue editor exports one track. All exports include a JSON cue backup and manifest. Use a new destination name each time.

In rekordbox, choose the XML under **Preferences → Advanced → Database → Imported Library**, enable the rekordbox XML browser source, then import the playlist. Rekordbox 7 accepted the generated XML source; collection import and cue alignment still need a manual check. No beat grid is exported. See [M5 verification](docs/M5_VERIFICATION.md).

## Playlists and metadata

Select library rows and enter a playlist name in the sidebar. Playlists can be renamed, reordered, and have tracks added/removed without copying or deleting audio. Drag a track handle, use its Up/Down keys, or use the move buttons; the saved order also controls playback and export. Select tracks and choose **Review** for sequential metadata editing. **Find matches** cleans download filenames and searches Apple Music and MusicBrainz independently when requested. Featured-artist credits are normalized for catalog retrieval. Results appear as each service responds and remain selectable while the other service is working. Artist, version and duration checks exclude incompatible results; inspect the remaining release/version before choosing one. Text matches are not audio identification. Local JPEG/PNG artwork, Apple release covers and up to 1200px Cover Art Archive release covers are supported. Switching a selected release clears artwork from the preceding release. **Save to library** stages changes. **Write tags** opens a review of saved changes before writing selected originals; each file gets a backup and an audio-identity check. **Reload file tags** discards library metadata edits and reads the source again.

**Auto metadata** searches and applies the best compatible catalog match and a verified album cover for each selected track. With no selection, it processes all tracks in the current library/playlist view (respecting search and filters). It runs in the background with progress and cancellation. Strong matches take priority, then similarity; tracks with weak matches or no usable release cover stay unchanged for **Review**. **Review** and **Review results** reopen the saved fields, artwork and candidate matches without another lookup. Changes apply to the library; **Write tags** remains the explicit step for modifying source files. Completed results survive restarting the app; interrupted work is reported without silently resuming.

Run `./scripts/setup-metadata-macos.sh` once to install the optional tag writer. The launcher discovers it automatically; `CRATELOOM_METADATA_PYTHON` overrides the interpreter. Mutagen is GPL-2.0-or-later and is currently installed separately, not bundled; distribution needs a dependency/license review. See [M3 verification](docs/M3_VERIFICATION.md) for tested formats and limits.

Metadata matching behavior, live examples, and the experimental ShazamKit boundary are recorded in [metadata matching verification](docs/METADATA_MATCHING_VERIFICATION.md).
The revised lookup, native titlebar and ordering checks are recorded in [metadata and ordering verification](docs/METADATA_ORDERING_FIX_VERIFICATION.md).

The detail waveform distinguishes individual beats and four-beat bars across the track. `Bar ~N.B` is provisional 4/4 numbering until you set bar 1. Use the `< 16 beats >` control for adjustable beat jumps (¼–64 beats), or Shift+Left/Right in the editor. Drag/two-finger scrubbing previews on display frames and commits the media seek on release. See [waveform grid verification](docs/WAVEFORM_GRID_VERIFICATION.md) for measured behavior and high-refresh test limits.


## Find Music and downloads

Open **Find Music** in the sidebar. Paste a public HTTPS audio-file URL, review the title/artist/version, then choose **Download & import**. The queue has progress, cancel/retry, source-quality details and **Open track**; BPM/RGB analysis starts after import. Original files go into `CRATELOOM_DATA/downloads` without conversion. Reviewed metadata is saved to the library; file tags change only through explicit Write tags.

Artist/title searches return MusicBrainz recording references. Paste a **YouTube or YouTube Music** link and choose **Find source → Download & import** when public audio is available. This requires separately installed yt-dlp and Deno (`brew install yt-dlp deno`). See [YouTube download verification](docs/YOUTUBE_DOWNLOAD_VERIFICATION.md).

Spotify and SoundCloud links show reference details. For SoundCloud, use the creator’s **Download file** option on SoundCloud when offered, then choose **Add local file**. [M4 verification](docs/M4_VERIFICATION.md) covers the direct HTTPS file route.


## Local macOS app bundle

Run `./scripts/build-app-macos.sh` from the checkout. The app bundles its engine; FFmpeg/ffprobe and the optional analysis, structure and tag runtimes are installed separately. The bundle uses `~/.crateloom` unless you set `CRATELOOM_DATA`. The tested Apple Silicon bundle is ad-hoc signed for local use. See [release checks](docs/M5_VERIFICATION.md) and the [dependency inventory](docs/DEPENDENCIES.md).

DJ-set tracklist and audio scans show centered progress with **Cancel scan**. Completed entries and samples are kept for Resume. See [scan progress verification](docs/SET_SCAN_PROGRESS_VERIFICATION.md) for source recovery and validation.

The library toolbar groups selection and export settings into dropdowns. Metadata review arrows save before moving between tracks, and the player artwork/title opens Cue Editor. DJ-set scans keep History and Current set available. For YouTube mixes requiring sign-in, select a browser under **Options → YouTube access** where the video is playable; public access remains the default. The macOS bundle includes a pinned YouTube extractor. See [interface and mix recovery verification](docs/INTERFACE_YOUTUBE_RECOVERY_VERIFICATION.md).
