# CrateLoom

A local-first DJ preparation application. This repository is an early development prototype, not a release: see [docs/PROGRESS.md](docs/PROGRESS.md) for the precise feature and verification boundaries.

## Development on macOS

Requirements: Node.js 22+, npm, Rust, Python 3, and `ffmpeg` and `ffprobe` on PATH. The current engine uses only Python's standard library. Run from the repository root:

```sh
./scripts/dev-macos.sh
```

If port 1420 is already in use, run `CRATELOOM_DEV_PORT=1421 ./scripts/dev-macos.sh` instead. Quit any older CrateLoom window using the same library before upgrading; schema migration creates a SQLite backup.

The native-storage copy avoids AppleDouble `._*` files generated by shared drives, which otherwise break Tauri capability parsing. The script refreshes the copy each time it runs. A Python executable can be selected with `CRATELOOM_PYTHON`. For the experimental frozen engine, set `CRATELOOM_ENGINE_EXEC` to its full path instead. See [M0 verification](docs/M0_VERIFICATION.md) for results and a hands-on checklist. The engine stores data in `~/.crateloom`; set `CRATELOOM_DATA` to isolate a test library. Original audio is referenced, not copied or modified. A development build needs the source tree and installed Python and FFmpeg; it is not a distributable app.

```sh
npm run build
npm test
python3 -m unittest discover -s engine/tests -v
CARGO_TARGET_DIR="$HOME/Library/Caches/CrateLoom/target" COPYFILE_DISABLE=1 cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml
```

## Optional beat and RGB analysis

On Apple Silicon macOS, run `./scripts/setup-analysis-macos.sh` once before starting the app to enable offline beat estimation and the frequency-colored waveform. See [M2 verification](docs/M2_VERIFICATION.md) for controls, testing and limitations. An optional local structure model adds automatically labeled sections after running `./scripts/setup-structure-macos.sh`; review its weight-license discrepancy and the labels before use.

## Try the local workflow

Add one WAV or MP3 and wait for its waveform to load. Open **Edit Cues**, seek and add a cue, edit its label or time, then try dragging its waveform marker and undo/redo. Quit and restart the app to check persistence. Export to a new XML filename and check the companion JSON backup. The source file is referenced and is never modified on import or export.

The audio-stream signature guards against applying cues to a replaced file. For a track imported by an earlier version, open it once while the original file is still unchanged to establish the signature. Missing files need to be restored to their original location; relinking is not implemented yet. Beat positions and cue suggestions are estimates to review; sections can be entered manually or generated by the optional model. BPM and global grid positioning are editable; flexible beat-warp markers are not yet available.

## Export

Select a track, open Edit Cues, and choose Export XML. CrateLoom writes XML referencing the original audio and a separate `.crateloom.json` cue backup. Choose a new name if a backup already exists. In rekordbox, select the XML in Preferences > Advanced > Database (the exact label can vary by version), enable the rekordbox XML source in the browser, then locate and import the playlist. Check cues and timing yourself. XML creation has been tested; actual rekordbox import and alignment have not. No beat grid is exported.
