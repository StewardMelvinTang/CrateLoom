# M4 discovery and acquisition — 2026-11-06

This is the M4 baseline. Public service reference support was added later; see [M5 verification](M5_VERIFICATION.md).

## Available workflow

**Find Music** accepts an artist/title query or a public HTTPS audio-file URL. Name searches return MusicBrainz recording references with release, artist, version and duration evidence. Selecting one stages its fields for review; it does not download or identify audio. Supply the artist’s direct file link for that version. Optional release artwork comes from Cover Art Archive. Title, artist and version remain editable before enqueueing.

The working acquisition adapter downloads original MP3, FLAC, WAV, AIFF, M4A and OGG files. Supported sources lists explicit URL-resolution, search, metadata, acquisition, format and authentication capabilities internally; the UI shows the effective availability. YouTube/YouTube Music and SoundCloud adapters are unavailable. Spotify URLs are recognized as references, but Spotify metadata lookup is not configured and audio acquisition is unavailable. There is no login, cookie import, stream ripping, web-page extraction or automatic source substitution. No provider is presented as implemented merely because yt-dlp supports it.

Downloads are serial, with stage/progress, cancel, retry, source details and Open track. After successful import, the existing BPM/RGB queue runs even when the source screen is closed. Imported download records are checked again on UI startup to recover a missed analysis handoff. Analysis retains its existing 15-minute limit and requires the optional analysis runtime; longer downloads can still be imported and prepared manually. Automatic section analysis is a separate optional action.

Reviewed fields/artwork are staged in the library on new imports. Downloaded bytes and embedded tags stay unchanged. A duplicate reuses the existing track, cues, sections and metadata; the redundant downloaded copy is removed. Duplicate detection uses exact stream identity and timing, not acoustic song recognition. A missing original stays missing until explicitly relinked.

## Persistence and quality

SQLite schema v11 adds acquisition reviews, state, progress, attempts, quality and provenance; an older library receives a SQLite backup before migration. Pending jobs resume serially when the queue is initialized after restart. Previously active jobs become Interrupted and require Retry. A retry starts the transfer again from the saved review; expired signed links need a fresh source resolution. The last 100 jobs are displayed, with at most 25 active/queued.

Files are downloaded to an isolated work directory, checked with ffprobe, hashed, and copied exclusively into `CRATELOOM_DATA/downloads` without overwriting existing files. New track metadata and the completed job commit together. Ordinary failure/cancellation removes partial and unpublished files and rolls back an in-flight import. An abrupt crash after file publication but before commit can leave a recoverable file in downloads; its last saved path is shown on the interrupted job. Inspect that file before retrying; retry may leave the earlier recovery copy in the folder. No disk/database cross-resource transaction or byte-range resume is claimed.

The route requires HTTPS on port 443, validates public destination addresses before connecting, retains TLS certificate/hostname validation, and repeats checks on redirects. It does not inherit proxy credentials or cookies. Transfers are bounded to 512 MB and 10 minutes, with a 10-second connection/read timeout. Cancellation during a blocking network read waits for that read or its timeout. Header size/ETag changes and incomplete responses fail; a known reference-duration conflict above max(12 seconds, 8%) also fails. Matching duration does not establish the exact recording or release.

Quality displays the actual codec/container, reported bitrate, sample rate, channel count, duration and byte size. Source/resolved URLs, SHA-256, selected reference and download time are stored. URL query strings are removed from public status/provenance to avoid exposing signed tokens; the original review URL is retained locally for retry. There is no transcoding, upsampling or claim that bitrate proves source fidelity. MP3 conversion remains a future explicit operation.

## Verification

A real download of **Monkeys Spinning Monkeys — Kevin MacLeod** completed from the artist’s HTTPS MP3 endpoint in an isolated library. Received/saved size: **5,005,207 bytes**; SHA-256: `a5bb345c23849ad0786aa0bc5157a9f2d4039660fe00282e55754d475f36dc14`. ffprobe reported MP3, 320,000 bit/s, 44,100 Hz, stereo, 125.0743 seconds. File SHA-256 matched the streamed download hash. The source was not transcoded and no test music was added to the owner library or repository.

The rendered React app resolved and reviewed that source, enqueued it, then switched to All Tracks. Import and automatic BPM/RGB analysis completed in the background, and Open track displayed the cached signal and beat grid. The detected tempo was 143.555 BPM; this single result is workflow evidence, not a musical-accuracy benchmark. Live MusicBrainz search returned two recording references, explicit selection required a separate file source, and the chosen release cover loaded. Spotify produced an unavailable/reference message rather than a download action. A second real transfer was cancelled through the UI, retried, and cancelled again; its attempt counter reached two, the library stayed at one track, and no partial file remained. Dark/light layouts, long Unicode fields and error states were checked with no horizontal overflow or uncaught page errors.

Backend regression coverage includes verified original bytes, staged metadata, duplicate cue protection, active/queued cancellation, retry, startup recovery, persisted queued reviews without an in-memory provider registry, invalid/truncated/oversize/changed sources, wrong reference duration, rollback during import, exclusive and Unicode-safe paths, private destinations, capability claims, HEAD-to-range fallback and immediate-completion job responses. The full Python suite passed **46 tests**, with the analysis, structure and metadata runtimes configured and no skips. The **13 Node tests**, frontend typecheck/production build and Rust bridge regression also passed. Existing import/playlist/metadata/tag-writing/grid/analysis tests are included. UI checks use isolated Edge and a loopback verification bridge into the real engine, with actual remote source requests. They do not substitute for native Rust asset-scope checks or owner playback testing.

Evidence artifacts are local at `~/Library/Caches/CrateLoom/m4-validation`: test output, UI results and dark/light screenshots at 1440×1000 and 900×800. An independent Impeccable finish review returned **ship** for the supplied current dark/light discovery UI captures, with no material fixes requested; that verdict covers the rendered UI addition, not native playback or provider reliability. No production network bypass or browser automation dependency was added to the app. The native Tauri development binary was rebuilt and launched against the existing owner library, and its Python sidecar remained running. Native visual interaction was blocked because macOS was locked; that check and audible playback remain for the owner. The existing library was migrated to v11 with a pre-migration SQLite backup; its track, cue, section and playlist rows matched that backup exactly. One later live MusicBrainz request did not return results within the UI test window; a subsequent retry returned two references. Catalog availability remains external.

## Owner check and remaining work

Open Find Music, paste a direct artist audio link, review its version and Download & import. Try Cancel/Retry, open the resulting track, and inspect Source & file. Search by name separately to see the reference-selection flow. A web-page link is deliberately rejected; get the direct audio file URL from the creator.

Other acquisition adapters, authenticated links, full-disk/removable-drive recovery, large download libraries, Windows, packaged dependencies, signing/notarization and real rekordbox import/alignment remain unverified or unimplemented. M5 is multi-track/playlist export followed by measured rekordbox import checks and packaging readiness. Owner acceptance of M3/M4 is pending.
