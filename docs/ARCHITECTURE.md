# Development architecture

React calls a restricted Tauri command. Rust holds one Python process and sends protocol-v1 JSON lines over stdin/stdout. Each message carries a request ID and params; responses carry the same ID and either a result or structured error. Stdout is reserved for the protocol. The Python engine alone writes the SQLite database, currently schema version 11. Tauri's asset scope is expanded only for imported track paths returned by the engine. The webview media element handles playback. FFprobe supplies metadata and FFmpeg decodes waveform data. A whole-file SHA-256 detects file changes; an FFmpeg audio-stream SHA-256 plus codec, sample rate and duration is used to recognize compatible tag-only changes. Legacy records receive a stream baseline when the unchanged original is next opened. This signature is not an acoustic fingerprint. The current implementation is deliberately incomplete; see PROGRESS.md before extending it.

M3 folder/multi-file import runs on one background thread in the Python host, with separate SQLite connections and per-file transactions. Import reports persist separately from the analysis-job table. Cancelling signals a thread-local event checked during hashing and FFmpeg/ffprobe polling; completed file results remain committed. Import status uses a sequence cursor with 100 results per response. Analysis IDs enter the existing frontend analysis queue as files finish; that analysis queue remains session-only. Relinking is identity-checked and the new path is granted through the restricted Tauri bridge.

Playlists store ordered track UUID references. `preparation.py` owns staged metadata and tag-write dispatch. `metadata_lookup.py` searches Apple Music and MusicBrainz on a bounded pool and publishes incremental results through the existing job endpoint. Metadata catalog requests use six-second network timeouts and per-provider start intervals (1.1 seconds for MusicBrainz, 3.1 seconds for Apple). Successful catalog caches expire after seven days; empty results expire after five minutes, and stale responses can be used with a warning during an outage. `metadata_matching.py` parses filename hints and ranks provider recordings by title, artist, version and duration. Catalog identity removes featured-title credits for retrieval without changing the shared identity used by set/source matching. Up to three MusicBrainz queries and one Apple search use a 50-recording cap per response. Responses are evaluated against the current track on every search. Release metadata stays separate from recording identity. Incompatible candidates cannot be selected in the editor; no text score is treated as audio identity or match probability. Cover requests use a separate 1200px MusicBrainz cache key or a server-resolved Apple recording ID. The optional Mutagen 1.48.1 worker edits a sibling temporary copy, reads back changed fields/artwork, checks compressed audio identity and timing, creates a verified backup, and atomically replaces the source. It emits a receipt before the host updates the stored file hash and clears pending changes. Reviewed batch writes include a revision token over pending fields and file identity; stale reviews are rejected. Every host SQLite context closes its connection after commit/rollback.

`metadata_batch.py` provides the opt-in Auto metadata workflow with two background workers. It ranks compatible matches, verifies a release cover before applying fields/artwork in one SQLite transaction, and checks a metadata/file snapshot before writing so concurrent manual edits win. A JSON journal records per-track progress and cancellation; separate review files keep candidate lists out of library-list responses. Review loads those cached candidates alongside the current fields and artwork. Completed results survive restart, and unfinished jobs become interrupted. Original file tags remain behind the explicit tag-write workflow.

`beat-grid.ts` and `beat_grid.py` complete a display grid while leaving detector output unchanged. The server uses the same completed positions for explicit bar-anchor validation; automatic cue evidence remains the original detections. `waveform-envelope.ts` holds exact min/max range levels and a bounded visual media clock. Scrub events update one animation-frame preview target; only gesture completion seeks the HTML media element. Beat jumps interpolate within the shared beat timeline and preserve fractional beat phase. See [waveform/transport checks](WAVEFORM_GRID_VERIFICATION.md).


M4 `providers.py` owns bounded source reviews and explicit adapter capabilities. It reuses the background provider-job protocol; initial responses are always pending, including immediately completed requests. MusicBrainz results are references, never acquisition URLs. Server-issued source IDs are scoped to the library and expire after one hour. `download_http.py` validates each HTTPS destination/redirect and connects to the validated public IP while retaining TLS hostname checks. HEAD inspection can fall back to range-request headers.

`acquisitions.py` owns a persistent serial queue, using separate SQLite connections and the existing cancellable import context. Completed jobs store the source review, actual media quality, hash and provenance. New imports, staged metadata and completed job state commit together; existing duplicate tracks remain unchanged. A verified original is published exclusively into the managed downloads directory; partial work is separate. Queued jobs resume on initialization; active jobs become interrupted after restart. The frontend polls independently of the Find Music workspace and hands completed tracks to automatic analysis, including missed handoffs recovered on startup. It does not persist the general analysis queue. See [M4 verification](M4_VERIFICATION.md) for crash windows and provider boundaries.


M5 adds bounded public service references through `service_links.py`; provider oEmbed HTML never enters the webview. Source pages open externally via an HTTPS host allowlist. `rekordbox_export.py` validates the selected assets and stages ordered XML, cue backup, manifest and optional byte-identical copies before exclusive publication. The UI runs export off the request thread and polls the existing background job protocol. A packaged macOS build locates its adjacent frozen engine and separately installed optional worker interpreters; the engine embeds worker sources for those interpreters and a CA bundle for HTTPS.

DJ-set scan jobs use `set_scan_jobs.py` for scoped cancellation and progress. Worker feedback is exchanged through atomic JSON snapshots; provider subprocess groups stop on cancellation, and partial recognition plans/checkpoints stay in SQLite. `youtube_tracklist.py` reads bounded public page metadata when the extractor fails. `scan_audio.py` tries audio-only formats and segmented transfer for the same video, verifies the finished file, and bounds its durable audio cache. Explicit cancellation disables continuation persistently; app shutdown preserves previously queued work without undoing a user cancellation.

The macOS bundle includes a checksum-pinned yt-dlp helper next to the engine. Mix acquisition prefers native transfer handling, verifies exact video identity, and can remux a supported muxed stream to audio for recognition. Scan controls carry an explicitly chosen browser session; `dj_set_youtube_access` stores only its browser name for report continuation. Public page/description/chapter extraction is independent of audio access, with bounded comment-tracklist recovery. UI disclosures share arrow/expansion behavior, dialog presence retains exit motion, and metadata review saves before changing tracks.
